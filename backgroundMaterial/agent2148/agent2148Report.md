## 2. Tooling Delivered (Main Agent)

Before launching the agents, the Main Agent built the data-entry surface so the user does not have to hand-edit JSON.

### 2.1 `pageContent` schema

Added to `docs/sign-object-spec.md` under "Page Content Object". Fields: `pageStatus`, `accentColor`, `themeName`, `headerTitle`, `photo`, `trailforks`, `linguistics` (with `primarySection`, `relatedForms`, `quickReference`, `baseWords`), `culturalStory`, `trailStory`, `sources`, `notes`.

### 2.2 Renderer — `tools/sign_page_renderer.py`

Standalone Python CLI that reads `pageContent` from `catalogue.json` and writes kiwapamitin-style HTML to `docs/{folder}/index.html`. Reuses the exact CSS, DOM, and cross-highlight JS of the exemplar; derives a full theme from a single `accentColor`. Skips any sign whose status is `draft` unless `--force` is passed. Smoke-tested with the kahkakiw pageContent transferred from the existing hand-built page.

### 2.3 Server endpoints — `tools/catalogue_editor_server.py`

Two new POST endpoints:

- `/api/save-sign-content` — validates and persists `pageContent` for a single sign in `catalogue.json`; optionally auto-renders the page.
- `/api/regenerate-sign-page` — re-renders one or more signs without changing the catalogue, useful when only theme or accent color is changed in the UI.

### 2.4 UI — Sign Page Content panel inside `docs/index.html`

Adds a third section to the existing editor-grid (alongside Final STL and Colours):

- Status badge + page-status select (`draft` / `agent-drafted` / `user-reviewed` / `published`)
- Accent colour picker
- Header title override (optional)
- Photo path + alt + caption
- Trailforks trail id, trail URL, optional widget URL override
- Cultural / contextual story heading + body (paragraphs separated by blank lines)
- Trail-builder personal story heading + body
- Linguistics JSON editor (textarea with monospace font)
- Curator notes
- Buttons: **Reload from catalogue**, **Save content**, **Regenerate page**, **Open rendered page** (new tab)

The panel is wired into the existing API-availability lifecycle so it disables itself when the local editor server is not running.

## 5. How the User Reviews Pilot Output

1. From the repo root: `python3 tools/catalogue_editor_server.py`
2. Open: <http://127.0.0.1:8765/docs/index.html>
3. Click a pilot sign card (kahkakiw, backbreaker, or kakwa).
4. In the right pane, the rendered page appears in the iframe. The middle pane's editor scrolls down to the new "Sign Page Content" section.
5. Change the accent colour, edit the story, fix a syllabic if the agent read it wrong, then click **Save content**. The page regenerates automatically and the iframe refreshes.
6. When satisfied, switch `Page status` to `user-reviewed`.
